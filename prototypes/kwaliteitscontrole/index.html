Drie modules, één keten

Module 1 bepaalt wat er gecontroleerd wordt, module 2 legt de controle vast in het veld, module 3 maakt er sturingsinformatie van voor de leidinggevende. De App en het Dashboard in deze pagina zijn module 2 en 3; module 1 is beschreven, niet gebouwd.

Grootste complexiteit · twee smaken

1. Plannen

  1. Input: wekelijkse TOOC lijst (week 39: 1.298 objecten in 48 routes met volgnummer)
  2. Alleen objecten die deze week onderhoud kregen
  3. Langst geleden gecontroleerd eerst
  4. Elke gemeente minimaal 1x per jaar, ook de kleine
  5. Geografisch gebundeld per regio en route
  6. Uitkomst: weekplanning per inspecteur in rijvolgorde
Smaak A: eigen deterministische formule, eerste versie nu al mogelijk op route en volgnummer uit de TOOC lijst. Smaak B: planning van Routigo als input. Voorkeur B, mits export en livegang passen.

App · module 2

2. Controleren

  1. Ronde in rijvolgorde op de telefoon, kaart toont waar je staat
  2. Object aantikken: Start controle of Meer over dit object
  3. Foto's volgens instructie: objectnummer, per campagne, schade
  4. Observaties: 7 controlepunten inspreken, AI structureert
  5. AI stelt vervolgvraag als informatie ontbreekt
  6. Afgerond: data direct bij het object, navigatie naar volgende
Geen naverwerking meer op kantoor. Werkt ook zonder dekking.

Dashboard · module 3

3. Sturen

  1. Webapplicatie voor de leidinggevende en Joost
  2. Risk dashboard: goed, aandacht nodig, actie nodig
  3. Doorsnede per gemeentelijk contract en per object
  4. Data van TOOC gekoppeld per object
  5. Prestaties per inspecteur: aantallen, fotokwaliteit, invoerkwaliteit, tijd per object
Bouwt volledig op de gestructureerde invoer uit module 2. Wat je in de App afrondt, verschijnt in het Dashboard.
